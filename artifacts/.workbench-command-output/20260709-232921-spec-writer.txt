# Implementation Notes

## Changed

- Fixed the four product/layout failures from `artifacts/visual_audit`.
  - `app-shell-workbench`: corrected the shell/body/workbench sizing path so the sidebar remains fixed, the workbench fills the remaining viewport, Body content has nonzero width, WorkbenchMain is visible, and StatusBar remains pinned in view.
  - `form-controls`: corrected the narrow theme-control probe row so it wraps instead of clipping into the following Text entry panel.
  - `layout-flex-stress`: restored `min-width: 0` shrink behavior for dense flexible controls and adjusted the impossible mobile action row to wrap.
  - `responsive-layout`: corrected the mobile probe constraints that intentionally forced a `440px` min-width panel into a `390px` viewport.
- Updated `native/src/layout.rs`.
  - Zero-sized flex-basis containers now measure descendants against available parent space instead of passing a hard zero content size.
  - Authored percent/calc dimensions now lock default flex growth unless the author explicitly sets flex growth, matching the existing percent/calc layout tests.
  - Explicit `min-width: 0` suppresses intrinsic leaf minimums for shrinkable dense controls, while nonzero min-width auto controls still get useful intrinsic widths.
  - Added `app_shell_workbench_body_uses_flex_basis_without_collapsing_content` regression coverage.
- Updated `python/dragongui/widgets.py`.
  - `WorkbenchLayout` now explicitly uses `flex: 1`, `flex_grow: 1`, and `flex_shrink: 1`.
  - `Body` no longer sets a hard default `width: 0`; it keeps flex-basis behavior without collapsing the cross axis.
  - `WorkbenchMain` no longer sets the `flex` shorthand by default, so fixed `height` overrides are not defeated by `flex-basis: 0`.
