# Spec: Visual Audit And Layout Root-Cause Pass For Professional Demo

## Goal

The new professional all-features demo was implemented, but the user reports major layout problems. Perform a visual-audit pass like the existing `artifacts/visual_audit` workflow, identify what went wrong in DragonGUI itself, and fix the underlying library/layout behavior where appropriate.

This is not just a demo cleanup task. The demo should be used as a realistic integration workload to expose product layout bugs, especially around app shells, body scroll ownership, splitters, fixed-height panels, narrow viewports, toolbar wrapping, text sizing, and plot/data widgets inside constrained containers.

## High-Priority Failure Areas

Inspect these first in the new demo screenshots and snapshots:

- App shell chrome:
  - Sidebar height/width when `.pro-shell` stacks on mobile.
  - MenuBar, top toolbar, tabs, body, and status bar vertical reservation.
  - Whether `StatusBar` remains visible and does not cover body content.
- Toolbar wrapping:
  - `IconButton`, `ToolbarSeparator`, `SearchBox`, `Spacer`, and `SmallButton` layout when width is constrained.
  - Whether CSS `flex-wrap` on `Toolbar` is honored correctly by native layout.
  - Whether wrapped toolbars compute height correctly and push following content down.
- Tabs and navigation:
  - Eight tabs in a narrow width.
  - Badges on tabs/nav items.
  - Long labels and disabled/active states.
- `Body` scroll ownership:
  - Pages are inside a single `Body(scroll="y", style={"height": 0, "flex": 1})`.
  - Verify content below fixed-height splitters and grids is reachable.
  - Verify no nested scroll area paints outside its clip.
- Splitter/Pane behavior:
  - Horizontal splitters in overview/explore/data/reports with pane min sizes that exceed mobile width.
  - Splitter should either scroll, stack, clamp, or fail gracefully; it must not overlap or create negative/zero-width child regions.
- Grid layout:
  - `GridLayout(columns=4, min_column_width=180)` metric cards at `390` and `320`.
  - `GridLayout(columns=2, min_column_width=360)` and `columns=3, min_column_width=300` at narrow widths.
  - Ensure grid collapse does not preserve impossible column widths.
- Plot/data widgets:
  - `Scatter3D`, `LinePlot`, `Histogram`, `Heatmap`, `BarChart`, `PieChart`, `DataFrameTable`, and `HtmlReport` inside fixed-height or splitter containers.
  - Check blank canvases, clipped axes/labels, broken scalar bars, table header overlap, and zero-size plot surfaces.
- Text:
  - Page title, breadcrumbs, metric values, long route names, property names, table headers, status text, and tooltip/modal text.
  - Text should wrap, ellipsize, clip within bounds, or receive more layout space intentionally.

## Implementation Guidance

Start with evidence, not assumptions:

1. Add the visual audit target(s) for the professional demo.
2. Run the audit for all routes at desktop and narrow sizes.
3. Open the generated screenshots manually.
4. For each visual defect, open the matching snapshot and record:
   - target id and size,
   - screenshot path,
   - affected widget/page,
   - observed failure,
   - relevant rects/clips/scroll values,
   - suspected module,
   - whether the root cause appears to be library behavior or demo misuse.
5. Write this defect inventory to `artifacts/IMPLEMENTATION_NOTES.md` before broad fixes.

Then fix in this order:

1. Catastrophic library layout bugs:
   - zero/negative width or height,
   - child overlap due to min sizes,
   - scroll content not reachable,
   - status/toolbar/tab/body reservation errors,
   - paint outside clip.
2. Text clipping/measurement failures.
3. Data/plot widget sizing and blank rendering.
4. Demo-level responsive adjustments for genuinely impossible layouts.
5. Audit/report status honesty.

Do not solve by merely shortening demo labels, deleting stress content, hiding pages, or removing mobile audit sizes.

## Edge Cases

- Splitter pane min sizes larger than available width.
- Horizontal splitters inside vertically scrolling bodies.
- Fixed-height chart/table/report widgets inside a scroll-owned page.
- Toolbar wrapping with spacers and intrinsic-width controls.
- Tabs with many labels and badges at `390px` and `320px`.
- Sidebar plus status bar plus body on mobile-stacked `AppShell`.
- Long unbroken route names in table cells, breadcrumbs, status labels, and property names.
- Grid layouts whose `min_column_width` exceeds narrow viewport width.
- Nested scroll areas inside panels and pages.
- Plot widgets that receive zero-size or clipped rects.
- HtmlReport/WebView unavailable or slow to initialize.
- High DPI rounding at panel/control/table borders.
- Audit wrapper must preserve import inertness and generated fixture behavior.
- Audit status must distinguish true pass, static fail, blocked capture, and manual interaction needs.

## Out Of Scope

- Replacing the new professional demo with another ground-up rewrite.
- Deleting the old `examples/all_features_v3_demo.py`.
- Removing feature coverage to avoid layout bugs.
- Hiding failures by reducing audit sizes, cropping screenshots, or shortening stress labels.
- Implementing full automated interaction playback for every menu/dropdown/modal state.
- Broad redesign of the public widget API.
- Rewriting the entire layout engine.
- Performance benchmarking beyond what is needed to make the audit reliable.
