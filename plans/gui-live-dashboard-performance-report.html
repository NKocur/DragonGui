The bug the benchmark found

What failed without coalescing

Python callback queue depth during the original DragonGUI high-load run

Validation correctly rejected this run. After a 15-second drain attempt, 318 Python tasks and 226 native commands remained; the displayed state stopped at tick 3,581 instead of 3,899. The queue high-water mark was 1,012.

Interpretation

DragonGUI’s GPU stage is not the main bottleneck.At high load, native frame work p95 was 0.89 ms while command drain p95 was 17.56 ms. The dominant cost is applying Python-originated changes and rebuilding affected retained content.
Coalescing makes overload bounded and correct.The recommended high-load run coalesced 1,410 obsolete tasks, held Python queue high-water to 1, drained fully, and finished on the correct final tick.
DragonGUI keeps substantially less high-load memory than Dear PyGui.Peak RSS was 432 MiB versus 814 MiB, although PyQtGraph remained lowest at 152 MiB.
The next optimization target is narrower retained invalidation.Updating 200 labels plus plot payloads creates heavy command application, layout, style, and text work. Batch property updates, avoid restyling unchanged nodes, and isolate text-only mutations from layout are the highest-value directions.

Method and fairness notes

Each framework displays the same deterministic data shapes and control counts. Low uses two 2k-point lines; medium uses four 10k-point lines; high uses six 50k-point lines plus a 50k-point scatter, a 128×128 heatmap, and 200 changing labels. Frameworks run in fresh processes. Synchronous event-loop adapters skip overdue scheduled generations; DragonGUI’s producer uses call_soon_threadsafe(..., coalesce_key="live-dashboard-frame"), which gives equivalent latest-state semantics.

Validation checks retained point counts, heatmap dimensions, final visible status, scheduled-tick accounting, and item existence. DragonGUI additionally checks native resources, renderer source counts, native retained text, layout diagnostics, and drained queues. One repetition makes this an engineering baseline rather than a statistically conclusive ranking.
